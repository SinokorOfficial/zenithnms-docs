    ZenithNMS API 참조 문서¶

    Base URL: http://localhost:3000/api (nginx가 /api/를 백엔드 컨테이너로 그대로 프록시) Swagger UI: 현재 미노출 — FastAPI 기본 /docs는 /api 프리픽스가 없어 위 프록시로는 접근 불가. 필요 시 백엔드 컨테이너 포트를 직접 열거나 docker compose exec backend로 접속. Content-Type: application/json (파일 업로드는 multipart/form-data) 인증: 아래 2장 참고 — 로그인 후 발급된 JWT를 Authorization: Bearer <token> 헤더로 전달

    1. 공통 규약¶

    응답 형식¶

    모든 응답은 JSON 형식입니다. 에러 응답:

    { "detail": "에러 메시지" }

    HTTP 상태 코드¶

    코드 의미
    200 성공
    201 생성 완료
    204 삭제 완료 (본문 없음)
    400 잘못된 요청
    401 인증 실패 (로그인/OTP 오류, 토큰 만료·누락)
    404 리소스 없음
    502 SNMP 통신 실패
    503 SNMP 라이브러리 사용 불가

    페이지네이션¶

    목록 조회 엔드포인트는 공통으로 limit / offset 쿼리 파라미터를 지원합니다.

    날짜/시간¶

    모든 datetime 필드는 ISO 8601 UTC 형식 (2026-04-29T03:48:59.531214Z)

    2. 인증 (Auth)¶

    Prefix: /api/auth

    단일 관리자 계정 + SMS(CoolSMS) OTP 2단계 인증 구조입니다. 자세한 흐름은 docs/manual.md 2장을 참고하세요.

    POST /api/auth/login¶

    이메일/비밀번호 검증 후 등록된 휴대폰 번호로 OTP 발송

    요청 본문

    필드 타입 필수 설명
    email string ✅ 관리자 이메일
    password string ✅ 비밀번호

    응답 

    { "detail": "OTP가 전송되었습니다.", "phone_masked": "010-****-2823" }

    에러 - 401: 이메일 또는 비밀번호 불일치

    POST /api/auth/verify-otp¶

    OTP 검증 후 JWT 액세스 토큰 발급

    요청 본문

    필드 타입 필수 설명
    email string ✅ 로그인 시 사용한 이메일
    otp string ✅ 6자리 인증번호 (5분 이내 유효)

    응답 

    { "access_token": "eyJhbGciOi...", "email": "admin@company.com" }

    에러 - 401: 인증번호 불일치 또는 만료

    POST /api/auth/logout¶

    응답: { "detail": "로그아웃 되었습니다." }

    서버 측에 세션 상태가 없으므로(Stateless JWT) 실질적으로는 클라이언트가 토큰을 폐기하는 것으로 로그아웃이 완료됩니다.

    GET /api/auth/me¶

    현재 토큰의 사용자 확인 (인증 필요)

    응답: { "email": "admin@company.com" }

    3. 헬스 및 대시보드¶

    GET /api/health¶

    API 서버 상태 확인

    응답 예시 

    {
  "status": "ok",
  "version": "1.0.0"
}

    GET /api/summary¶

    대시보드용 전체 현황 요약 (장비 수 + 활성 알람 수)

    응답 스키마 

    {
  "devices": {
    "total": 8,
    "up": 7,
    "down": 1
  },
  "alerts": {
    "active": 3,
    "critical": 1,
    "warning": 2
  }
}

    4. 장비 (Devices)¶

    Prefix: /api/devices

    장비 객체 (DeviceOut)¶

    {
  "id": 7,
  "hostname": "SW-L3-HQ-01",
  "ip_address": "192.168.0.131",
  "device_type": "switch",
  "location": "HQ-2F",
  "vendor": "Cisco",
  "model": "WS-C3560X-24",
  "status": "up",
  "snmp_version": "v2c",
  "snmp_community": "public",
  "snmp_port": 161,
  "last_polled": "2026-04-29T03:48:59.531214Z",
  "poll_interval": 60,
  "enabled": true,
  "alert_enabled": true,
  "remark": null,
  "created_at": "2026-04-28T02:05:26.235578Z"
}
    필드 설명
    alert_enabled false면 이 장비는 알람 평가에서 제외됨 (점검 중 일시 차단용)
    remark 시스템 탭에 표시되는 자유 메모 (최대 3000자)

    GET /api/devices/stats¶

    장비 상태별 통계

    응답 스키마 

    {
  "total": 8,
  "up": 7,
  "down": 0,
  "warning": 0,
  "unknown": 1
}

    GET /api/devices¶

    장비 목록 조회

    쿼리 파라미터

    파라미터 타입 기본값 설명
    status string — 상태 필터 (up, down, warning, unknown)
    type string — 유형 필터 (router, switch, server, firewall, ap, unknown)
    enabled boolean — 활성/비활성 필터
    search string — 호스트명 또는 IP 주소 검색 (부분 일치)
    limit int 200 최대 반환 수 (max: 1000)
    offset int 0 페이지네이션 오프셋

    응답: DeviceOut[]

    POST /api/devices¶

    장비 등록

    요청 본문

    필드 타입 필수 기본값 설명
    hostname string ✅ — 호스트명
    ip_address string ✅ — IP 주소 (중복 불가)
    device_type string — unknown 장비 유형
    location string — null 위치
    vendor string — null 제조사
    model string — null 모델명
    snmp_port int — 161 SNMP 포트
    snmp_version string — v2c SNMP 버전 (v1, v2c, v3)
    snmp_community string — public SNMP 커뮤니티 문자열
    snmp_v3_username string — null SNMPv3 사용자명
    snmp_v3_auth_protocol string — null SNMPv3 인증 프로토콜 (MD5, SHA)
    snmp_v3_auth_password string — null SNMPv3 인증 패스워드
    snmp_v3_priv_protocol string — null SNMPv3 암호화 프로토콜 (DES, AES)
    snmp_v3_priv_password string — null SNMPv3 암호화 패스워드
    poll_interval int — 60 폴링 주기 (초)
    enabled boolean — true 폴링 활성화 여부

    응답: DeviceOut (HTTP 201)

    에러 - 400: 동일 IP 주소 이미 등록됨

    SNMPv3 자격증명은 데이터베이스에 암호화 없이 저장됩니다.

    GET /api/devices/{device_id}¶

    장비 단건 조회

    경로 파라미터: device_id (int)

    응답: DeviceOut

    에러 - 404: 장비 없음

    PUT /api/devices/{device_id}¶

    장비 정보 수정

    경로 파라미터: device_id (int)

    요청 본문: POST와 동일한 스키마 (미전송 필드는 기존 값 유지)

    응답: DeviceOut

    PATCH /api/devices/{device_id}/remark¶

    시스템 탭의 비고(REMARK) 메모만 단독 수정

    경로 파라미터: device_id (int)

    요청 본문: { "remark": "점검 예정 2026-09-01" }

    응답: DeviceOut

    PATCH /api/devices/{device_id}/alert¶

    알람 활성화 토글 (점검 중 알람 일시 차단용)

    경로 파라미터: device_id (int)

    요청 본문: { "alert_enabled": false }

    응답: DeviceOut

    DELETE /api/devices/{device_id}¶

    장비 삭제 (관련 메트릭·알람·인터페이스 함께 삭제)

    경로 파라미터: device_id (int)

    응답: 없음 (HTTP 204)

    GET /api/devices/{device_id}/interfaces¶

    장비 인터페이스 목록 (간략 정보)

    경로 파라미터: device_id (int)

    응답 스키마 

    [
  {
    "id": 12,
    "ifindex": 1,
    "ifname": "GigabitEthernet0/1",
    "ifdescr": "GigabitEthernet0/1",
    "ifspeed": 1000000000,
    "if_oper_status": 1,
    "if_admin_status": 1
  }
]

    필드 설명
    if_oper_status 운영 상태 (1=Up, 2=Down)
    if_admin_status 관리 상태 (1=Up, 2=Down)

    GET /api/devices/{device_id}/detail¶

    장비 상세 정보 — SNMP 수집 전체 데이터 (최근 2시간 기준)

    경로 파라미터: device_id (int)

    응답 스키마 

    {
  "id": 7,
  "hostname": "SW-L3-HQ-01",
  "ip_address": "192.168.0.131",
  "status": "up",
  "device_type": "switch",
  "system": {
    "sys_descr": "Cisco IOS Software ...",
    "sys_name": "SW-L3-HQ-01",
    "sys_uptime_secs": 864000,
    "sys_uptime_str": "10일 0시간 0분 0초",
    "sys_location": "HQ Server Room",
    "sys_contact": "admin@company.com",
    "last_polled": "2026-04-29T03:48:59.531214Z"
  },
  "interfaces": [
    {
      "id": 12,
      "ifindex": 1,
      "ifname": "Gi0/1",
      "ifdescr": "GigabitEthernet0/1",
      "ifalias": "Uplink to Core",
      "ifspeed_bps": 1000000000,
      "if_oper_status": 1,
      "if_admin_status": 1,
      "in_bps": 15234567.0,
      "out_bps": 8432100.0,
      "in_errors": 0,
      "out_errors": 0,
      "in_discards": 0,
      "out_discards": 0
    }
  ],
  "resources": {
    "cpu_util": 12.5,
    "mem_util": 43.2
  },
  "protocols": {
    "ping_rtt_ms": 0.45,
    "ping_loss_pct": 0.0,
    "icmp_in": 12450,
    "icmp_out": 12449,
    "tcp_curr_estab": 3,
    "udp_in": 98234,
    "udp_out": 95123
  }
}

    섹션 설명
    system SNMP MIB-II sysGroup 정보 (sysDescr, sysName, 가동시간 등)
    interfaces IF-MIB 인터페이스 목록 + 실시간 트래픽/오류/폐기 카운터
    resources CPU/메모리 사용률 (벤더 자동 감지 + 다중 MIB 폴백 전략으로 수집, docs/manual.md 14장 참고)
    protocols Ping RTT/손실, ICMP/TCP/UDP MIB-II 카운터

    에러 - 404: 장비 없음

    GET /api/devices/{device_id}/disks¶

    가장 최근 폴링 사이클에서 저장된 디스크 스냅샷 조회 (DB 캐시, device_sys_state.disk_info)

    경로 파라미터: device_id (int)

    응답 스키마 

    [
  { "desc": "C:\\", "total_bytes": 107374182400, "used_bytes": 53687091200, "free_bytes": 53687091200, "util_pct": 50.0 }
]

    서버 유형 장비에서만 의미 있는 데이터가 채워집니다 (docs/manual.md 7장 자원 탭 참고).

    GET /api/devices/{device_id}/disks/live¶

    DB 캐시를 건너뛰고 지금 즉시 SNMP로 hrStorageTable을 다시 조회 (새로 추가된 디스크가 아직 폴링되지 않았을 때 사용)

    경로 파라미터: device_id (int)

    응답: /disks와 동일한 스키마

    에러 - 503: SNMP 라이브러리 사용 불가 - 502: SNMP walk 실패

    GET /api/devices/{device_id}/disk-debug¶

    hrStorageTable의 모든 항목을 필터링 없이 반환하는 진단용 엔드포인트 — 특정 드라이브가 디스크 카드에 안 보일 때 원인 확인용

    경로 파라미터: device_id (int)

    응답 필드: idx, type_raw(원시 OID), desc, alloc_unit, total_gb/used_gb/util_pct, is_memory, is_win_drive, included(현재 필터 통과 여부), reason

    GET /api/devices/{device_id}/snmp-diag¶

    5. 메트릭 (Metrics)¶

    Prefix: /api/metrics

    메트릭 타입 (metric_type)¶

    값 설명 단위
    cpu_util CPU 사용률 %
    mem_util 메모리 사용률 %
    ping_rtt Ping 평균 RTT ms
    ping_loss Ping 패킷 손실률 %
    if_in_octets 인터페이스 수신 속도 bps
    if_out_octets 인터페이스 송신 속도 bps
    if_in_errors 인터페이스 수신 오류 count
    if_out_errors 인터페이스 송신 오류 count
    if_oper_status 인터페이스 운영 상태 1=Up / 2=Down

    GET /api/metrics/device/{device_id}¶

    시계열 메트릭 데이터 조회

    경로 파라미터: device_id (int)

    쿼리 파라미터

    파라미터 타입 필수 기본값 설명
    metric_type string ✅ — 메트릭 타입 (위 표 참조)
    interface_id int — null 인터페이스 ID (인터페이스 메트릭 필터)
    start datetime — 24시간 전 조회 시작 시각 (ISO 8601)
    end datetime — 현재 조회 종료 시각 (ISO 8601)
    resolution string — raw 해상도 (raw, hourly, daily)
    limit int — 1440 최대 데이터 포인트 수 (max: 10000)

    응답 스키마

    "time": "2026-04-29T03:00:00Z",

  }

    GET /api/alerts/thresholds¶

    알람 임계값 목록

    응답 스키마 

    [
  {
    "id": 1,
    "device_id": null,
    "vendor": null,
    "model": null,
    "metric_type": "cpu_util",
    "warning_value": 80.0,
    "critical_value": 95.0,
    "enabled": true
  }
]

    device_id/vendor/model 모두 null = 전체 장비에 적용되는 전역 임계값. 적용 우선순위(장비 > 벤더+모델 > 벤더 > 서버 유형 기본값 > 전역)는 docs/manual.md 11장 참고.

    POST /api/alerts/thresholds¶

    알람 임계값 생성 (장비별 또는 전역)

    요청 본문

    필드 타입 필수 기본값 설명
    device_id int — null 지정 시 해당 장비 전용 임계값
    vendor string — null 벤더 전용 임계값 (device_id와 함께 쓰지 않음)
    model string — null vendor와 함께 지정 시 벤더+모델 전용
    metric_type string ✅ — 메트릭 타입
    interface_id int — null 특정 인터페이스 한정
    warning_value float — null 경고 임계값
    critical_value float — null 위험 임계값
    duration_secs int — 0 임계값 지속 시간 (초)
    enabled boolean — true 임계값 활성화

    응답: ThresholdOut (HTTP 201)

    PUT /api/alerts/thresholds/vendor¶

    벤더(선택적으로 모델까지) 단위로 CPU/메모리 임계값을 한 번에 upsert — 대시보드의 "제조사별 임계치 설정" UI가 사용

    요청 본문

    필드 타입 필수 설명
    vendor string ✅ 대상 벤더
    model string — 지정 시 벤더+모델 전용, 미지정 시 벤더 전체
    cpu_warning / cpu_critical float — CPU 임계값
    mem_warning / mem_critical float — 메모리 임계값
    enabled boolean — 기본 true

    응답: ThresholdOut[] (cpu_util, mem_util 두 행 upsert 결과)

    PUT /api/alerts/thresholds/{thr_id}¶

    알람 임계값 수정

    10. 지오 위치 (Geo)¶

    Prefix: /api/geo

    장비 IP를 위경도로 변환해 지도 시각화에 사용합니다. 공인 IP는 외부 ip-api.com을 호출하고(응답은 프로세스 메모리에 캐시), 사설 IP는 장비의 location 문자열을 키워드로 매칭해 대략적 좌표를 추정합니다.

    POST /api/geo/batch¶

    여러 IP를 한 번에 조회 (공인 IP는 최대 100개씩 배치 처리)

    요청 본문 

    [
  { "ip": "203.0.113.10", "location": "" },
  { "ip": "192.168.1.1", "location": "서울 본사" }
]

    응답 

    {
  "203.0.113.10": { "lat": 37.5, "lng": 127.0, "city": "Seoul", "country": "Korea", "private": false },
  "192.168.1.1":  { "lat": 37.5, "lng": 127.0, "city": "서울",  "country": "Korea", "private": true }
}

    GET /api/geo/{ip}¶

    단일 IP 조회 (하위 호환용 — 라우팅 충돌 방지를 위해 /batch보다 뒤에 등록됨)

    응답: 사설/루프백은 { "lat": null, "lng": null, "private": true }
